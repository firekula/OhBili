# Feature Specification: 动态页与个人主页（用户空间）

**Created**: 2026-11-17
**Status**: Approved
**Input**: User description: "登录成功了，可以继续完成动态页和个人主页功能"（经范围澄清：动态全类型渲染、任意用户空间页、仅 phone）

## Overview

为 OhBili phone 端补齐两大缺失能力：**动态页**——登录用户在"动态" tab 浏览关注 UP 主的动态流，全类型渲染（视频/图文/转发/专栏/番剧/纯文字等），支持刷新与分页；**个人主页**——通用的用户空间页（含登录用户自己），展示用户资料、粉丝数据与投稿视频列表，供全应用各处点击头像/昵称进入。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览视频类动态 (Priority: P1)

登录用户打开"动态" tab，看到关注 UP 主的最新动态列表；其中视频投稿类动态以卡片形式展示（封面、标题、时长、播放/弹幕数据、UP 主头像昵称、发布时间），点击卡片进入视频播放页。

**Why this priority**: 视频投稿是动态流中出现频率最高、价值最大的类型，是动态页的核心可用性底线；仅实现本故事即构成可用 MVP。

**Independent Test**: 登录后进入动态 tab，列表出现视频动态卡片，点击任一卡片能进入播放页并正常播放。

**Acceptance Scenarios**:

1. **Given** 已登录且关注的 UP 主有视频投稿动态，**When** 打开动态 tab，**Then** 列表展示该动态卡片（封面/标题/时长/数据/UP 主信息/时间）
2. **Given** 动态列表已展示视频动态，**When** 点击该动态卡片，**Then** 跳转到视频播放页并开始加载播放
3. **Given** 动态列表已展示视频动态，**When** 点击 UP 主头像或昵称，**Then** 跳转到该 UP 主的个人主页

---

### User Story 2 - 查看任意用户个人主页 (Priority: P1)

用户从任一入口（视频播放页 UP 主信息、动态页 UP 主头像/昵称、我的页头部）点击进入某用户的空间页：顶部展示头像、昵称、等级、签名，数据区展示关注数/粉丝数/获赞数，下方以网格展示其投稿视频列表，支持上拉分页加载，点击视频进入播放页。

**Why this priority**: 个人主页是全应用用户探索的汇聚点，且数据获取路径独立于动态流，可与动态页并行交付。

**Independent Test**: 在任一视频播放页点击 UP 主昵称，进入该 UP 主空间页，资料与数据正确展示，投稿列表可加载并点击进入播放页。

**Acceptance Scenarios**:

1. **Given** 用户在视频播放页，**When** 点击 UP 主头像或昵称，**Then** 进入该 UP 主的空间页，展示头像/昵称/等级/签名/关注数/粉丝数/获赞数
2. **Given** 已进入某用户空间页，**When** 持续滚动到底部，**Then** 投稿视频列表继续分页加载，无重复条目
3. **Given** 已进入某用户空间页，**When** 点击任一投稿视频，**Then** 跳转到视频播放页并正常播放
4. **Given** 用户在"我的"页已登录，**When** 点击我的页头部区域，**Then** 进入自己的空间页（mid 为登录用户）

---

### User Story 3 - 图文与文字动态渲染 (Priority: P2)

图文动态（带图动态）展示文字内容与图片九宫格（最多 9 图），点击任一图片进入全屏预览（黑底大图，可左右滑动切换、点击关闭）；纯文字动态仅展示文字内容；文字过长默认折叠，可展开。

**Why this priority**: 图文是动态流第二高频类型，补齐后动态页覆盖绝大多数内容形态。

**Independent Test**: 动态列表中出现图文动态时正确渲染九宫格；点击图片进入全屏预览并可滑动切换、关闭。

**Acceptance Scenarios**:

1. **Given** 动态流中有图文动态（多图），**When** 列表渲染，**Then** 文字与九宫格图片完整展示
2. **Given** 图文动态已渲染，**When** 点击其中一张图片，**Then** 进入全屏预览，可左右滑动切换图片，点击任意处关闭
3. **Given** 动态流中有纯文字动态，**When** 列表渲染，**Then** 文字内容正确展示，超长文本折叠且可点击展开

---

### User Story 4 - 转发动态渲染 (Priority: P2)

转发动态展示转发者信息、转发理由（文字）与被转发的原动态内容（按原动态类型以对应样式嵌套渲染：原动态为视频时渲染视频卡片并可点击进播放页；为图文时渲染九宫格；其余类型降级为文字提示）。

**Why this priority**: 转发是动态流常见形态，嵌套渲染保证信息完整。

**Independent Test**: 动态列表中出现转发动态时，可见转发者、转发理由与原动态内容；原动态为视频时可点击进入播放页。

**Acceptance Scenarios**:

1. **Given** 动态流中有转发视频动态的条目，**When** 列表渲染，**Then** 展示转发者/转发理由/嵌套原视频卡片
2. **Given** 转发动态内嵌视频卡片，**When** 点击该卡片，**Then** 进入视频播放页

---

### User Story 5 - 专栏/番剧等其他类型降级展示 (Priority: P3)

专栏、番剧/影视、合集更新等其他类型动态以简化卡片展示（封面+标题或文字摘要），点击提示"该类型内容暂不支持查看"（不白屏、不崩溃）。

**Why this priority**: 长尾类型出现频率低，降级展示保证列表完整性与稳定性。

**Independent Test**: 构造或遇到此类动态时列表项正常渲染且点击仅提示，无异常。

**Acceptance Scenarios**:

1. **Given** 动态流中出现专栏/番剧类动态，**When** 列表渲染，**Then** 以简化卡片展示（不出现空白项或报错）
2. **Given** 专栏/番剧类动态已渲染，**When** 点击卡片，**Then** 页面提示"该类型内容暂不支持查看"，不跳转、不崩溃

---

### User Story 6 - 动态流刷新与分页 (Priority: P2)

动态列表支持下拉刷新（重新加载第一页）与上拉加载更多（按游标分页追加），加载过程有加载态提示，全部加载完成后提示"没有更多了"。

**Why this priority**: 动态流是持续消费的内容，分页体验是基础要求。

**Independent Test**: 下拉列表触发刷新回到最新；滚动到底部触发加载更多；翻尽后出现"没有更多了"提示。

**Acceptance Scenarios**:

1. **Given** 动态列表已展示，**When** 下拉刷新，**Then** 列表回到最新动态并替换原内容
2. **Given** 动态列表已展示，**When** 滚动到底部，**Then** 追加加载下一页动态
3. **Given** 所有动态页已加载完毕，**When** 再次滚动到底部，**Then** 显示"没有更多了"，不再发起请求

### Edge Cases

- 未登录访问动态 tab：保持现有"你还未登录 + 去登录"引导，不发起动态请求
- 动态接口返回空列表（如新账号无关注）：显示空态提示（如"暂无动态，去关注喜欢的 UP 主吧"）
- 空间页用户不存在或已注销：展示明确的错误态提示，不白屏
- 空间页用户无投稿：投稿列表区域显示空态提示
- 接口请求失败/网络异常：页面展示可重试的错误态（非崩溃、非白屏）
- 转发动态的原动态已被删除：原内容区域展示"原动态已失效"提示
- 图文动态图片数量为 1 时：单图以合理尺寸展示（不强撑九宫格）
- 动态中的视频卡片被点击后，播放页所需的视频基础信息从动态数据中正确构造（标题/封面/UP 主/数据），缺失字段有默认值
- 自己的空间页与他人空间页渲染一致（同一页面，mid 不同）
- 登录态失效后再进入动态 tab：接口返回未登录数据时，引导重新登录而非死循环加载

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 动态 tab 在已登录时 MUST 展示关注 UP 主的动态流（动态 feed 接口），未登录时 MUST 保持现有登录引导
- **FR-002**: 动态流 MUST 全类型渲染：视频投稿（卡片，可进播放页）、图文（文字+九宫格+全屏预览）、纯文字、转发（嵌套原动态）、专栏/番剧/合集等（简化卡片+降级提示）；未知类型 MUST 降级展示不崩溃
- **FR-003**: 动态流 MUST 支持下拉刷新与上拉游标分页；翻尽后 MUST 显示"没有更多了"
- **FR-004**: 图文动态 MUST 支持点击图片进入全屏预览（左右滑动切换、点击关闭）
- **FR-005**: 超长文字内容（动态文字/转发理由）MUST 默认折叠并可展开
- **FR-006**: 系统 MUST 提供通用用户空间页：头像/昵称/等级/签名 + 关注数/粉丝数/获赞数 + 投稿视频网格列表（分页）
- **FR-007**: 用户空间页 MUST 可从以下入口进入：视频播放页 UP 主头像/昵称、动态页 UP 主头像/昵称、"我的"页头部（自己的空间）
- **FR-008**: 投稿视频列表 MUST 支持上拉分页加载，点击视频进入播放页
- **FR-009**: 空间页数据展示 MUST 与 B 站公开数据一致（昵称/头像/签名/等级/粉丝/关注/获赞/投稿）
- **FR-010**: 各列表接口请求 MUST 携带现有登录凭证（Cookie），失败时 MUST 展示可重试的错误态且不影响已有页面数据
- **FR-011**: 本功能范围 MUST 仅限 phone 产品；tablet 代码 MUST 不受影响
- **FR-012**: 所有交互 MUST 为只读：不提供点赞/评论/转发/关注/发动态等写操作

### Key Entities *(include if feature involves data)*

- **动态条目（DynamicItem）**: 一条动态，包含作者信息（头像/昵称/mid）、发布时间、动态类型、正文内容、类型化主体（视频/图文/转发原动态/专栏/番剧等）、互动数据（转发/评论/点赞数）
- **动态类型（DynamicType）**: 视频投稿、转发、图文、纯文字、专栏、番剧/影视、合集更新、其他/未知
- **用户资料（UserProfile）**: mid、头像、昵称、等级、签名、关注数、粉丝数、获赞数
- **投稿视频（ArchiveVideo）**: 投稿列表项，含封面、标题、时长、播放/弹幕数据、发布时间、bvid，可映射为现有视频卡片数据模型
- **游标（FeedCursor）**: 动态流分页游标，由响应返回、请求透传

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登录用户打开动态 tab，3 秒内出现动态列表（网络正常时）
- **SC-002**: 动态流中视频/图文/转发/文字/专栏番剧各类型均能正确渲染，无一类型导致页面崩溃或空白
- **SC-003**: 从三个指定入口（视频页/动态页/我的页）均能在 2 次点击内到达对应用户的空间页
- **SC-004**: 空间页资料数据（昵称/粉丝数等）与 B 站网页端同一用户数据一致
- **SC-005**: 动态流与投稿列表均可流畅完成"刷新 + 至少 3 次分页加载"操作，无重复条目、无卡死
- **SC-006**: phone 端全功能可用，tablet 端行为与改动前完全一致

## Assumptions

- 动态流与空间页依赖现有扫码登录凭证（SESSDATA 等）；用户已通过扫码完成登录
- B 站动态 feed、用户空间、投稿列表等公开接口持续可用；个别风控敏感接口失败时按错误态降级
- 全屏图片预览采用轻量自绘实现（黑底大图+滑动切换），不引入三方图片库
- 等级、获赞等字段若接口未返回，展示为"--"等占位而非报错
- 动态与空间页视觉风格沿用现有首页/视频页设计语言（同字号/圆角/间距体系）
- 视频播放页沿用现有路由与参数协议（传入视频基础信息对象）
- tablet 端保持现状（占位页），后续周期再评估

## Open Questions

- 动态 feed 与投稿列表的 B 站接口存在风控可能（部分接口需 WBI 签名/设备指纹），若实测被风控，优先切换到备选接口或调整请求策略——在架构设计阶段确定主/备选接口方案
- "我的"页头部进入自己空间页时，是否需要在空间页提供"编辑资料"等自有入口：本期按只读处理（不做编辑）
